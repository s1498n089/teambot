# 別人都怎麼做?—— A2A × MCP 生態的四種典型作法

> 這份文件接在 `TUTORIAL.md` 第 9 章之後讀最順。你只需要知道兩件事就能往下:
> **MCP 是 agent 接工具的接口、A2A 是 agent 之間對話的接口**(第 5、9 章講過)。
>
> 所有星數與狀態都是 **2026-07-26 用 GitHub API 實查**的快照 ——
> 你讀到的時候可能已經變了,但**四類的形狀不會那麼快變**。

---

## 讀法:四類都用同一個模板

為了不讓你每讀一類就要重新適應,下面四類全部照同一個順序講:

1. **他在解什麼問題**
2. **生活裡的樣子**
3. **他怎麼解**
4. **實例與現況**(附星數、還活著嗎)
5. **下場**

學會第一類的讀法,後面三類就只是換內容。

**還有一件事先講**:我們**故意把死掉的那一類放第一個**。因為看過一次失敗,
你才會自然想問「那後來的人怎麼辦?」—— 後面三類就有了存在的理由。

---

## 第一類:獨立翻譯橋 —— 已經死掉的那條路

### 他在解什麼問題

MCP 和 A2A 是兩套不同的接口。你的 Claude 只會講 MCP,對面的 agent 只會講 A2A,
兩邊接不起來。

### 生活裡的樣子

兩個人講不同語言,**請一個翻譯站中間**。A 說一句、翻譯翻給 B,B 回一句、翻譯翻回來。

### 他怎麼解

寫一個程式當中間人:對你的 Claude 來說,它是一個普通的 MCP 工具;
但它收到指令後,會轉成 A2A 的話講給對面的 agent 聽。

Claude 完全不知道 A2A 存在,它只覺得自己在用一個工具。

### 實例與現況

`GongRzhe/A2A-MCP-Server` —— 這個品類**星數最高**的一個。

| 項目 | 數字 |
|---|---|
| 星數 | 148 |
| 狀態 | **已封存**(作者主動宣告不再維護) |
| 最後一次改程式 | **2025-06-18** |

同品類的其他專案,星數全都在 25 以下,而且多半也停更了。

### 下場:**廢棄**

一個品類裡**最紅的那個都封存了**,其餘全是十幾顆星的小專案 —— 這就是「這條路沒人走」的樣子。

**為什麼死?** 兩個原因疊在一起:

1. **太早到場**:真正在寫 A2A 的人還很少(細節見最後的小百科),翻譯橋的客人根本還沒出生
2. **座位被預訂了**:等 A2A 的人多起來,那個位子已經被第三類(框架內建)佔走了

一句話:**早到,而且位子被預訂了。**

---

## 第二類:把一整團 agent 包成一顆工具

### 他在解什麼問題

第一類想讓 Claude 「學會講 A2A」。這一類換個想法:**Claude 不用學,
我直接把整套多 agent 系統包成一顆按鈕給它按。**

### 生活裡的樣子

你打電話到一個服務窗口說「幫我查這件事」。窗口後面其實有十個人分工合作,
但你只面對一個窗口,裡面怎麼運作你不用管。

### 他怎麼解

- 自己寫兩個(或更多)長駐服務,它們之間用 A2A 互相交辦
- 再把「這一整套」包成**單一一個 MCP 工具**
- 你的 Claude Code 按下那顆工具,背後一整團 agent 就開始跑

注意一個關鍵:在這個架構裡,**你的 Claude 是「按按鈕的人」,不是團隊成員**。

### 實例與現況

`ryabinski-labs/a2a-mcp-bridge`

| 項目 | 數字 |
|---|---|
| 星數 | **0** |
| 狀態 | 活躍(2026-07-22 還在更新) |
| 建立時間 | 2026-06-03 |

**這個專案的來歷要說精確**,因為我們自己一開始就講錯過:
它是 Anthropic 與 Google Cloud 合辦的一場 webinar(講題是「用 MCP 與 A2A 部署多 agent 系統」)
的**開源配套專案**。但它自己的說明文件寫得很清楚:

> 「Not an official Anthropic or Google product.」(非 Anthropic 或 Google 的官方產品)

也就是說:**它跟著官方教材走,但它本身不是官方出品。** 這兩件事差很多。

### 下場:**教學用途,不是產品路線**

0 顆星但**幾天前還在更新** —— 這個組合本身就說明它的定位:**它是教材,不是產品**。
教材沒人 star 很正常,你不會去 star 一份講義。

這一類的價值在於「示範怎麼搭配兩個協定」,不在於「做出一個大家都在用的東西」。

## 第三類:框架直接內建 —— 最多人走的路

### 他在解什麼問題

前兩類都在處理「怎麼把協定接起來」。這一類問了一個更根本的問題:
**為什麼要讓使用者自己接?框架自己會講不就好了。**

### 生活裡的樣子

不請翻譯了,**直接雇用本來就會兩種語言的員工**。

### 他怎麼解

你用框架寫 agent 的時候,框架本身就會講 MCP(多數也會講 A2A)。
你只管寫「這個 agent 要做什麼」,協定的事框架在底下處理掉了。

**結果是:使用者根本感覺不到協定的存在。**

### 實例與現況

`google/adk-python` —— 選它當代表,是因為它跟 A2A 出自同一家(Google),
是「協定直接長進框架裡」最純粹的樣子。

| 項目 | 數字 |
|---|---|
| 星數 | **20,877** |
| 狀態 | 活躍 |

同品類的其他框架也都是萬星級,而且都活著:

| 框架 | 星數 |
|---|---|
| `crewAIInc/crewAI` | 56,123 |
| `langchain-ai/langgraph` | 38,128 |
| `microsoft/agent-framework` | 12,390 |

### 下場:**顯學**

這是四類裡**使用者最多**的一條路,而且差距不是一點點 —— 是「五萬顆星」對上「一百多顆星」。

**它為什麼贏**:因為它讓協定變成**看不見的東西**。
使用者要的從來不是「我要用 A2A」,而是「我要我的 agent 能跟另一個 agent 合作」。
框架把後者做掉了,前者就沒人在乎。

> 補一個提醒:`microsoft/autogen` 有 **59,965 顆星**,比上面每一個都多 ——
> 但它**已經停更三個月**,微軟自己轉去做 `agent-framework` 了。
> 星數是歷史,不是現況。這件事下面的小百科會再講。

## 第四類:港口 / 閘道 —— 正在起飛的那條路

### 他在解什麼問題

前三類都在解「兩個 agent 怎麼講話」。這一類**換了一個層次**:

> 當公司裡有幾十個 agent、幾百個工具的時候,問題已經不是「能不能講話」,
> 而是「**誰能用誰、誰在用什麼、出事了怎麼查**」。

### 生活裡的樣子

不是讓兩艘船學會互相喊話,而是**蓋一座港口**:所有船都靠這裡,
港口有登記簿(誰是誰)、有海關(能不能進)、有紀錄(誰來過)。

### 他怎麼解

架一個統一入口擋在所有 agent 與工具前面:

- **登記簿(registry)**:有哪些 agent、哪些工具,集中登記
- **海關(guardrails)**:誰能呼叫誰、什麼內容不准過
- **單一門口**:外面的程式只要認識這個門口,不必認識後面幾十個服務
- **多節點串連(federation)**:多個港口之間可以互通

### 實例與現況

`IBM/mcp-context-forge`

| 項目 | 數字 |
|---|---|
| 星數 | **4,140** |
| 分支數 | 770 |
| 狀態 | 活躍(**查詢當天還在推送**) |
| 授權 | Apache 2.0 |

品類熱度的佐證(不只 IBM 一家在做):

| 專案 | 星數 | 是什麼 |
|---|---|---|
| `docker/mcp-gateway` | 1,504 | **Docker 官方**做的閘道 |
| `luckyPipewrench/pipelock` | 781 | 專門做 MCP 安全的防火牆 |

### 下場:**新興,而且正在起飛**

判斷依據不是感覺,是三個訊號同時出現:

1. IBM 這種等級的公司投入,而且**當天還在推送**
2. **Docker 官方入場** —— 基礎設施廠商進場,通常代表這件事要變成標配
3. 出現了**周邊生態**(專門的安全防火牆),那是品類成熟的徵兆

**它為什麼活**:因為它做的事是**框架不做的** —— 框架讓你的 agent 會講話,
但不會幫你管理「公司裡三十個 agent 誰能碰哪些資料」。那是另一個問題,而且是公司一定會遇到的問題。

## 小百科:怎麼自己看懂一個生態

這一節可能比上面四類更耐用 —— 上面的數字會過期,下面的方法不會。

### 一、星數是「我覺得這重要」,不是「我在用」

看這組對照:

| 協定 | 協定本體星數 | Python SDK 星數 | 落差 |
|---|---|---|---|
| MCP | 88,886 | 23,723 | 約 4 倍 |
| A2A | 25,001 | **2,045** | 約 **12 倍** |

**協定本體**是「我看好這個方向」,**SDK** 才是「我真的要動手寫」。

MCP 是每四個看好的人裡有一個動手;A2A 是**每十二個看好的人裡才有一個動手**。

所以 A2A 現在的狀態是:**很多人在看,真正在寫的還很少。**
第一類會死,這是主因。

### 二、星數是歷史,最後推送日才是脈搏

`microsoft/autogen` 59,965 顆星,聽起來是霸主 —— **但它三個月沒動了**。

星數只會累積,不會減少。一個專案就算今天被放棄,它昨天累積的星還在那裡。
**要看它還活著沒有,得看「最後一次改程式是什麼時候」。**

在 GitHub 上這個欄位叫 `pushed_at`;另外還有一個 `archived`,
那是作者親口宣告「我不維護了」—— 第一類那個 148 星的專案就是這樣死的。

### 三、公信力來自出處,但「出處」要查到底

第二類那個專案自稱是「Anthropic × Google Cloud webinar 的開源配套」。
那句話**是真的**。但它的說明文件下面幾行還寫著「非官方產品」。

**我們一開始只讀到前半句,就在教學裡寫成「等於兩家東家親自示範」** ——
那是過度延伸,後來查了原文才更正。

> **別人怎麼自述,跟他實際是誰,是兩件事。**
> 尤其當你要拿它當論證的支柱時,要一路讀到免責聲明那一行。

## 收尾:四類看完之後,有一件事很奇怪

回頭看這四類,它們解的問題不同、下場也不同,但有一個**共同點**:

> **沒有任何一類,讓「買來就是完成品的 AI」(Claude Code、Codex 這種)
> 當那個「被別人呼叫」的角色。**

在這四類裡,你的 Claude 永遠是**發起的那一方**:它按工具、它呼叫別人、它透過框架去找別的 agent。

**它從來不是那個「被找上門」的成員。**

這不是巧合,原因寫在 `TUTORIAL.md` 第 9 章(簡單說:那類產品沒有大門)。
而我們這個專案在做的事,剛好就是那條沒人走的第五條路 —— 但那是另一個話題了。
